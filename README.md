# Song Bottle

노래 하나를 보내고, 낯선 누군가의 음악을 받는 익명 음악 교환 웹앱입니다.

**실제 사용자 간 교환 버전입니다.** 준비된 가짜 상대나 샘플 교환 기록을 사용하지 않습니다.

## 실행

Node.js 22.16 이상이 필요합니다. 현재 개발 PC에서는 22.17로 검증했습니다.

```sh
npm install
npm run dev
```

기본 주소는 http://localhost:5173 입니다. 포트가 사용 중이면 `PORT` 환경 변수를 바꿉니다.

PowerShell 예시:

```powershell
$env:PORT = '5174'
npm run dev
```

## 제출 시연

1. 일반 브라우저와 시크릿 창을 각각 엽니다. 동일 브라우저의 일반 탭들은 같은 사용자입니다.
2. 각 창에서 서로 다른 음악 URL을 입력합니다.
3. 양쪽에서 `J-pop` 등 같은 장르를 선택합니다. 무드는 서로 달라도 되고 비워두어도 됩니다.
4. 해류 코드도 같게 맞춥니다. 둘 다 비워두어도 됩니다.
5. 첫 번째 사람은 대기하고, 두 번째 사람이 보내면 교환됩니다.
6. 첫 번째 화면에도 최대 약 4초 뒤 결과가 도착합니다.
7. 교환 기록, 플레이리스트, 즐겨찾기, 텍스트 내려받기를 확인합니다.
8. 설정에서 프로필 아이콘과 색상을 바꾸고 첫 교환 도전과제와 50 XP를 확인합니다.

다른 PC/휴대폰에서는 배포된 동일한 HTTPS 주소를 사용해야 합니다.

## 교환 규칙

- 서로 다른 사용자의 서로 다른 곡을 1:1로 교환합니다.
- 장르를 반드시 선택하며 장르와 해류 코드가 같은 사람끼리 교환합니다.
- 조건에 맞는 대기 보틀 중 랜덤으로 선택합니다. 분위기 태그는 매칭에 영향을 주지 않습니다.
- 무드는 30가지 중 최대 3개까지 선택할 수 있으며 비워두어도 됩니다.
- 한 사용자당 대기 보틀은 하나입니다. 기록에서 회수할 수 있습니다.
- 같은 곡은 발송 시각부터 1시간 이후에 다시 보낼 수 있습니다. 회수해도 제한은 유지됩니다.
- 대기 보틀은 7일 뒤 만료됩니다. 상태는 다음 API 요청 때 갱신합니다.
- 교환 내용은 SQLite에 저장합니다. 새로고침과 서버 재시작 후에도 유지됩니다.

## 현재 범위

곡 링크를 붙이면 제목과 커버를 자동 조회합니다. YouTube와 SoundCloud는 공개 oEmbed, Spotify는 공개 oEmbed, Apple Music은 iTunes Lookup을 사용합니다. 자동 조회가 실패해도 전송할 수 있고 연필 버튼으로 직접 수정할 수 있습니다.

YouTube 작성자는 실제 아티스트와 다를 수 있어 채널로 표시합니다. Spotify oEmbed는 아티스트를 제공하지 않을 수 있으므로 이 경우 제목·커버만 자동 입력합니다. 임의 웹사이트를 크롤링하거나 HTML을 그대로 삽입하지 않습니다.

음악 재생은 원래 서비스에서 합니다. 짧은 리디렉션 링크 중 `spotify.link`, `on.soundcloud.com` 등은 지원하지 않습니다.

프로필은 고정 아이콘 6종과 색상 6종을 조합합니다. 교환 완료마다 25 XP, 100 XP마다 레벨 상승이며 도전과제 5종은 추가 경험치를 줍니다. 경험치는 완료된 기록에서 서버가 계산하므로 재요청이나 보틀 회수로 늘지 않습니다.

기존 DB는 시작할 때 새 열만 추가합니다. 이전 보틀의 장르는 빈 값으로 보존하며, 예전 대기 보틀은 회수하고 장르를 선택해서 다시 보내야 합니다. 같은 곡의 1시간 제한은 그대로 적용됩니다.

익명 접속 키는 브라우저에 저장되어 기기 간 동기화·계정 복구가 없습니다. 곡과 메시지는 사용자 입력 텍스트로만 표시합니다. 신고는 DB에 저장되고 신고자 화면에서 숨겨지며 자동 전역 차단은 하지 않습니다.

현재 설정 안내는 실제 저장 동작을 설명하는 안내문입니다. 공개 장기 운영 전에는 운영자 연락처, 데이터 삭제 절차와 신고 관리 화면을 추가해야 합니다.
